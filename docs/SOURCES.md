# Primary Sources And Design Implications

Reviewed 2026-09-18. Links support architectural choices; they do not constitute legal advice or product certification.

| Source                                                                                                                                                                                                                   | Verified point                                                                                                                  | Consequence for Eir                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| [DeepSeek Harness architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) and [Cordis primer](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/cordis-primer.md) | Harness composes services through plugins, dependency declarations, profiles and reversible effects                             | Small runtime, declared services, profile replacement and cleanup; no harness code copied        |
| [Inera NPÖ](https://www.inera.se/tjanster/alla-tjanster-a-o/npo---nationell-patientoversikt/)                                                                                                                            | Professional identity, HSA assignments, patient relationship, consent, restrictions and logged access are distinct requirements | Dedicated integration and policy work; a role string or FHIR API does not imply NPÖ connectivity |
| [Inera SITHS authentication](https://www.inera.se/tjanster/alla-tjanster-a-o/autentiseringstjanst-siths/)                                                                                                                | Identity and authorization attributes depend on the identity infrastructure and directory                                       | Production identity adapter and HSA mapping need an actual test tenant                           |
| [E-hälsomyndigheten NLL handbook](https://www.ehalsomyndigheten.se/verksamhet/nationella-lakemedelslistan/ansluta-till-nationella-lakemedelslistan/handbok-for-vard--och-apotekstjanster/)                               | NLL uses FHIR interfaces with its own specifications and requirements                                                           | Separate NLL adapter, contract tests and onboarding                                              |
| [HL7 Sweden SEBasePatient 1.0.0](https://hl7.se/fhir/ig/base/1.0.0/StructureDefinition-SEBasePatient.html)                                                                                                               | Personnummer and samordningsnummer use distinct identifier namespaces                                                           | Export uses those namespaces without asserting full profile conformance                          |
| [Skatteverket coordination numbers](https://www.skatteverket.se/privat/folkbokforing/samordningsnummer.4.5c281c7015abecc2e201130b.html)                                                                                  | Coordination-number day component is offset by 60                                                                               | Use established validator and keep identity type explicit                                        |
| [IMY access control and logs](https://www.imy.se/verksamhet/dataskydd/dataskydd-pa-olika-omraden/vard/informationssakerhet--for-vardgivare/kontroll-av-atkomst-till-uppgifter---for-vardgivare/)                         | Providers must document user access and systematically review access logs                                                       | Durable reads/denials plus an operational log-review milestone                                   |
| [TEHIK information centre](https://www.tehik.ee/en/information-centre) and [FHIR services](https://teabekeskus.tehik.ee/et/standardid/hl7/fhir)                                                                          | Estonia's exchange includes CDA and a transition to FHIR services                                                               | Support versioned national adapters, not a single global exchange assumption                     |
| [MedCom FHIR](https://medcom.dk/standarder/fhir/) and [test/certification](https://medcom.dk/standarder/test-og-certificering/)                                                                                          | Danish exchange uses profiled FHIR and governed testing                                                                         | Country packs need operational message contracts and validation                                  |
| [Commission EHDS milestones](https://health.ec.europa.eu/ehealth-digital-health-and-care/european-health-data-space-regulation-ehds_en)                                                                                  | Phased application includes 2029 patient-summary/prescription/dispensation exchange and 2031 images/labs/discharge              | Track implementing acts and maintain a compliance evidence map per product release               |

The quoted 2026 eHealth maturity scores from the earlier brief are not independently verified here. They are not reproduced as measured capabilities of Eir. National access maturity and the quality/completeness of a practice EHR are different measurements.
